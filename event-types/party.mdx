Use **Party** for guest registration without an admission charge. It starts with **Free RSVP** and a suggested capacity of 100. The template does not make the event private automatically.

## Template starting point

| Setting | Initial choice |
|---|---|
| Schedule | One day |
| Admission | Free RSVP |
| First offer | No admission charge (RSVP) |
| Capacity | 100 |
| Attendees choose a time | Not enabled |

These are editable suggestions, not recommended prices or venue limits. Replace the dates, price, and capacity with your own. See [how onboarding works](./overview#complete-onboarding).

## Choose the onboarding answers

Open **Create Event** in the selected workspace.

1. Select **Party** and name the celebration.
2. Set **One day** and the correct start/end, including the next calendar date when a party finishes after midnight.
3. Keep **Free RSVP** and enter the actual guest limit, or switch to **Paid tickets** if you charge admission.

<Note>**Create my event** may publish immediately when the requirements are met. Use **Continue later** to finish setup as a draft. Review any plan or publishing message before sharing the event.</Note>

## Finish the event settings

| Where to go | What to configure |
|---|---|
| **Event Details → Privacy** | Choose whether to hide the listing or require an access code on the hosted page. See [privacy controls](/event-management/eventdetails#privacy). |
| **Venue & Location** | Add the venue and arrival information guests need. |
| **Additional Info** | Collect relevant guest details and choices, with [per-ticket attendee collection](/event-management/additional-information#collect-answers-from-every-participant) when every person needs a record. |
| **Email Communication** | Set confirmations and reminders with the arrival time and contact instructions. |
| **Waitlist** | Use a [capacity-based waitlist](/event-management/waitlist) when the guest list has a firm limit. |

## Guest limits and privacy are independent

Hiding a party from listings does not block someone who has its direct URL. A hosted-page access code and the overall event capacity solve different problems. Test the experience you intend before sharing invitations. Review the number of guests permitted per order rather than assuming a plus-one field creates an additional attendee or reserves an extra place.

## Check the attendee experience

- Open the event as a guest and test the intended access restriction.
- Register the intended party size and check the actual number of attendee records.
- Verify an overnight end date, venue details, and confirmation wording.

Review the event’s saved status and [publish/share controls](/event-management/manage-events) when it is ready. Return to [all event types](./overview) to compare starting points.
