Once you’ve set up the Venue & Location details, the next step is to create and manage your event tickets. The Tickets section lets you define how attendees can join your event — whether through free, paid, or donation-based tickets. You can customize pricing, set quantities, apply sales tax, and even offer promo codes for discounts.

## Navigation and prerequisites

Open **Events**, create or edit the event, then select **Tickets**. Create a ticket or open an existing ticket to edit its fields. Some controls are conditional on ticket type, site platform, or plan. An upgrade prompt identifies an unavailable feature.

Set up [brand colors and logo](../branding-and-design/brand-design) first. For Shopify events using seating, dates/time slots, access codes, or quantity controls, configure the [Ticket Selector](../plugins/connect-shopify#configure-the-ticket-selector-for-advanced-ticketing).

Use the [current ticket options reference](./ticket-options-reference) to locate each field. The main editor groups settings into Details, Pricing & Access, Sales & Capacity, Check-in, Autopilot, and Seat Categories. The custom day editor uses its own section labels and is documented in [Date-specific Tickets](./day-specific-tickets).

## Sales Tax

The **Sales Tax** field appears for supported non-Shopify sites. For events sold as Shopify products, configure tax in Shopify and verify the storefront checkout.

Add a sales tax to your tickets, and it will be automatically applied at checkout. The configured percentage changes the checkout total; choose the rate appropriate to your event.  
For example, if your ticket price is 50 dollar and you set a 10% sales tax, the total amount charged at checkout will be 55 dollar.

> **INFO:** Leave this as it is if you don’t need to apply any tax to your ticket sales.

## Hidden tickets and access codes


<Frame caption="Hidden tickets can use an access code. Shopify events also offer Include in Shopify Variant.">
  <img src="../assets/refresh/event-management/ticket-hidden-access.png" alt="Hidden tickets can use an access code. Shopify events also offer Include in Shopify Variant." style={{ width: "100%", maxWidth: "100%", height: "auto" }} />
</Frame>

1. In **Pricing & Access**, enable **Hidden ticket** to hide the ticket from normal public selection.
2. Enter an **Access Code** if attendees should be able to reveal and buy it by entering that code. Leaving the code blank does not create a code to share.
3. On a Shopify site, review **Include in Shopify Variant**. Hidden tickets are excluded from Shopify product variants by default; enabling this explicitly includes the hidden ticket in those variants.
4. Save the ticket and update the event. Test the public selector without a code, with the correct code, and with an incorrect code.

A ticket access code is different from a private event's access code. Hiding an event listing is also different from restricting a ticket.

Choose how you want to charge for this ticket:

### Free  

Select this option if you would like your attendees to register for the event at no cost.

### Paid  

This option activates the **Price** field, which allows you to define the ticket cost that attendees will pay for registering for the event.

### Pay What You Want  

When you select this option, attendees have the flexibility to decide how much they wish to pay.  
Additionally, you can specify a minimum amount in the **Minimum Price** field.  
For example, if you set the minimum price to 30, attendees can choose to pay 30 or any higher amount.

For Shopify, follow the [pay-what-you-want checkout instructions](/plugins/shopify-ticket-selector#pay-what-you-want-tickets-on-shopify), including its supported ticket combinations and payment-confirmation requirements.

### Enable Service Fee  

Toggle this option ON to apply a custom booking fee to each ticket. When enabled, the **Custom Service Fee** field becomes active, allowing you to enter a fixed amount. The specified fee will then be added to the ticket price.

## Sales and Capacity Settings


<Frame caption="Set ticket inventory separately from the minimum and maximum quantity in each order.">
  <img src="../assets/refresh/event-management/ticket-capacity-order-limits.png" alt="Set ticket inventory separately from the minimum and maximum quantity in each order." style={{ width: "100%", maxWidth: "100%", height: "auto" }} />
</Frame>

<Frame caption="This example opens sales 24 hours before the event and closes them one hour before it starts. Start sales immediately removes the opening offset.">
  <img src="../assets/refresh/event-management/ticket-sales-window.png" alt="This example opens sales 24 hours before the event and closes them one hour before it starts. Start sales immediately removes the opening offset." style={{ width: "100%", maxWidth: "100%", height: "auto" }} />
</Frame>

This section helps you control when your tickets go on sale, when they stop selling, and how many can be sold — ensuring you stay within your event’s capacity limits and manage ticket availability effectively.

### Ticket Sales Start  

Set when ticket sales should begin relative to the event’s start time.

- Specify a value in **days, hours, or minutes** before the event.

- Alternatively, turn **Start sales immediately** **ON** to start sales instantly, which disables manual input.

### Ticket Sales End  

Set when ticket sales should stop, either before the event starts or before it ends.

- Specify a time offset using days, hours, or minutes according to your event’s requirements.

### Ticket Capacity 

Define how many tickets can be sold for this type. You can also set:

- **Min Per Order:** Minimum number of tickets a buyer must purchase.  
- **Max Per Order:** Maximum number of tickets per purchase.


## Required Ticket


<Frame caption="Require a minimum quantity of another ticket in the same order. This example requires one Standard ticket.">
  <img src="../assets/refresh/event-management/ticket-required-ticket.png" alt="Require a minimum quantity of another ticket in the same order. This example requires one Standard ticket." style={{ width: "100%", maxWidth: "100%", height: "auto" }} />
</Frame>

Use **Required Ticket** to require a minimum quantity of another ticket **in the same order**. For example, a Child ticket can require at least one Adult ticket.

1. Create and save the prerequisite ticket first, such as **Adult**.
2. Create or edit the dependent ticket, such as **Child**.
3. In **Required Ticket**, enable **Require another ticket to purchase**.
4. Choose the prerequisite under **Required ticket**. Only other saved tickets are offered; a ticket cannot require itself.
5. Set **Minimum quantity** to a whole number of at least 1.
6. Read the summary, such as “This ticket requires at least 1 Adult ticket in the same order.”
7. Save the ticket and update the event.

This is an order minimum, not a ratio: requiring 1 Adult does not mean 1 Adult for every Child. It does not automatically add the prerequisite ticket. **Min Per Order** controls the quantity of the ticket being edited; Required Ticket controls another ticket. A **Group Ticket** bundles component tickets instead.

Test an order containing only the Child ticket, then an order with the required Adult quantity. Also remove the Adult ticket from the test order and check the validation. Keep the prerequisite available during the dependent ticket's sales window, with enough capacity and compatible access rules.

Required Ticket is available on Business and higher. If the dropdown has no choices, save another ticket first.

## Advance Purchase Window


<Frame caption="Require advance booking sets the minimum number of days before the event when this ticket can be bought.">
  <img src="../assets/refresh/event-management/ticket-advance-purchase.png" alt="Require advance booking sets the minimum number of days before the event when this ticket can be bought." style={{ width: "100%", maxWidth: "100%", height: "auto" }} />
</Frame>

In **Sales & Capacity**, enable **Require advance booking** and enter **Days in advance** to require booking at least that many days before an event. This is a minimum booking lead time, not the maximum distance into the future a customer can book.

For example, 10 days means dates closer than 10 days are unavailable for purchase. Check the date picker around the cutoff before promoting it, and review the event timezone and other sales-window settings.

<Frame caption="Delayed entry opens check-in after the event starts. If both opening rules are enabled, delayed entry takes priority.">
  <img src="../assets/refresh/event-management/ticket-checkin-rules-delayed.png" alt="Delayed entry opens check-in after the event starts. If both opening rules are enabled, delayed entry takes priority." style={{ width: "100%", maxWidth: "100%", height: "auto" }} />
</Frame>

<Frame caption="Set the opening time before the event and the cutoff after it starts. A cutoff alone does not prevent early scans.">
  <img src="../assets/refresh/event-management/ticket-checkin-rules-window.png" alt="Set the opening time before the event and the cutoff after it starts. A cutoff alone does not prevent early scans." style={{ width: "100%", maxWidth: "100%", height: "auto" }} />
</Frame>

<Frame caption="Control how many times a ticket can be scanned and its validity after purchase.">
  <img src="../assets/refresh/event-management/ticket-checkin-rules.png" alt="Control how many times a ticket can be scanned and its validity after purchase." style={{ width: "100%", maxWidth: "100%", height: "auto" }} />
</Frame>

These settings control scanning, independently of when a ticket can be purchased. They are available on Business and higher.

| Control | Fields and effect | Example for an 18:00 start |
|---|---|---|
| **Early Check-In Window** | Enable, set **Check-in opens (before start)** and **Unit**. Controls the earliest scan before the event starts. | 1 hour opens check-in at 17:00. |
| **Late Check-In Cutoff** | Enable, set **Check-in closes (after start)** and **Unit**. Controls when admission closes after the start. | 2 hours closes check-in at 20:00. |
| **Delayed Check-In Window** | Enable, set **Check-in opens (after start)** and **Unit**. Opens admission after the event has started. | 30 minutes opens check-in at 18:30. |

Delayed Check-In takes priority over Early Check-In if both are enabled. Do not set a closing time earlier than the effective opening time. Review the editor's scan-window summary and test before, inside, and after the permitted window. **Entries allowed** and **Ticket Validity Period** remain separate constraints. Entries allowed is the scan limit (0 means unlimited); validity can be Unlimited, One Day, One Week, One Month, or One Year after purchase.

## Autopilot


<Frame caption="An Autopilot rule combines timing relative to the event with an action. Review the resulting timeline before saving.">
  <img src="../assets/refresh/event-management/ticket-autopilot.png" alt="An Autopilot rule combines timing relative to the event with an action. Review the resulting timeline before saving." style={{ width: "100%", maxWidth: "100%", height: "auto" }} />
</Frame>

<Frame caption="Autopilot can hide or show a ticket, change its price, or change its inventory.">
  <img src="../assets/refresh/event-management/ticket-autopilot-actions.png" alt="Autopilot can hide or show a ticket, change its price, or change its inventory." style={{ width: "100%", maxWidth: "100%", height: "auto" }} />
</Frame>

The Autopilot tab allows you to create automated rules that modify ticket properties based on time triggers relative to your event’s start or end time. Rules can hide or show a ticket, change its price, or change its inventory.

### How It Works

Click the **Add rule** button to create your first automation rule.

Each rule defines when and how a ticket property should change, using time-based conditions and actions.

| S.no | Field | Description |
|------|--------|-------------|
| 1 | **Enabled** | Shown for saved rules. Turn a rule on or off; disabled rules remain saved but inactive. |
| 2 | **Trigger Value** | Set the numerical trigger value (e.g., 1). |
| 3 | **Unit** | Choose Minutes, Hours, or Days. |
| 4 | **Timing** | Select Before Event Starts or Before Event Ends. |
| 5 | **Action** | Choose Hide ticket, Show ticket, Change price, or Change inventory. The current editor combines the action type and action choice. |
| 6 | **New value** | Enter the new amount for Change price or Change inventory. Hide/Show needs no amount. |

>**INFO:** You can similarly add additional rules at any time by clicking the **Add rule** button, or remove existing ones whenever needed by clicking the **Trash** icon.
Click on the **Create** button to proceed. Your ticket will be created successfully.

<Frame caption="Compare inventory, sold tickets, and what remains available to sell. The row controls edit, duplicate, and delete; the left handle changes order.">

The saved ticket table shows **Name**, **Price**, **Ticket inventory**, **Sold**, **Available to sell**, status, and row actions. **Available to sell** can be lower than inventory because event capacity is shared across ticket types. A group ticket uses the number of attendee spots in its composition; the table shows that requirement when applicable.

The **Event capacity** panel shows used and remaining attendee spots, or **Unlimited**. Sales stop when a ticket's inventory or the overall event capacity is reached. Status messages distinguish **Ticket sold out**, **Event at capacity**, and **Unavailable**.

- Use the pencil to **Edit ticket**.
- Use **Duplicate ticket** to create a similar offer, then review its name, price, inventory, dates, and restrictions.
- Drag the row handle to change ticket order. Sorting a column changes the table view; dragging changes the saved order.
- **Delete ticket** opens **Confirm Delete**. **No** keeps the ticket; **Yes** confirms removal. Do not use deletion to handle a paid attendee refund.

Promo Codes allow you to offer **discounts or special pricing** to your attendees. You can create limited-time offers, early-bird discounts, or group incentives to drive more ticket sales and reward specific audiences.

To create a new promo code, click **Create Promo Code**.

  <img src="../assets/refresh/event-management/promo-shopify-tags.png" alt="Open a saved promo’s Shopify Tags tab. Create and save the promo code first. Edit the saved code, open **Shopify Tags**, enter the exact customer tag and select **Add Tag**. Tags must match capitalization. A matching customer can receive that promo automatically at checkout. Remove a mapping with its tag remove control, and test a signed-in customer with and without the tag.
